# 在指定分类归档文献并标注稿件

**开始前确认目标分类和交付位置。** 用户已在本次任务中说明的内容直接沿用。缺少信息时，一次问清“用哪个个人库或群组库、哪个分类完整路径？标记直接写进原稿、另存副本，还是只在回复中给出？”直接写原稿或另存副本时，还需能确定源文件。在同一文库出现同名分类时，用父分类路径或真实分类键核对。新建分类、跨库复制和归档到其他分类都需要用户另行指定。

1. **核对文献。** 优先使用作者给出的文献。需要找证据时，建议在可用时使用 **Consensus 插件**（`@Consensus`）搜索，再打开原论文或 PubMed、出版社记录核实题名、作者、年份、DOI 或 PMID，以及它实际支持哪句话。用研究概念与关键词检索，无需提交原稿全文。已有确定的文献可直接进入归档。
2. **导入或归档到指定分类。** 同库已有条目沿用真实键，并核对是否属于所选分类。缺失的文献用已核实的书目信息导入。对已同步的个人库或群组库，可用具有该库写权限的 Zotero Web API 在桌面端关闭时完成。先预览所解析的分类和条目，再在用户指定范围内写入，并回读核实成员关系。仅在本地保存的库或缺少云端权限时，由用户在 Zotero 中归档并提供真实标记及分类确认。参考 [归档与标记工具用法](references/preparation.md)。
3. **按用户选择交付。** 选择原稿，就在该 DOCX 的指定句子处用 `mark_docx.py --in-place` 写入纯文本标记，交付同一路径。选择副本，就写入指定的新路径。选择只回文字，就在对话中返回标好的原句。标记放在其支持的句子或分句旁，保留原文、书签、图表、已有引文和书目。定位歧义或文档被占用时说明具体位置或原因，保留用户选择的交付方式。
4. **核对标记。** 每条依次是前缀、可读作者年份、定位信息、后缀和真实条目标识，以四个半角竖线分隔，两端用半角花括号。个人库用 `zu:用户ID:条目键`，群组库用 `zg:群组ID:条目键`。同处合引按原顺序紧邻排列，页码在第三字段。已给出的标记保留前后缀和作者显示设置。缺键或证据不足的文献单列在正文外。
5. **把最终确认交给作者。** 准备工作止于分类内的书目记录和稿件中的纯文本标记。交付时说明目标分类、实际归档情况、标记位置及稿件路径。作者打开并同步 Zotero，在 Word 中审阅标记，将光标放到书目位置，核对同一分类，再亲自点击 **确认转换引文并打开参考文献表**。此时才把标记转换成活动域并调用 **Add/Edit Bibliography**。助手不代点按钮、不调用 Word 宏，也不在后台生成活动引文或书目。
